Summary

The service answers one question deterministically: which stored memory belongs in this turn's context? It runs before the Turn Brain, is driven purely by cheap signals and storage reads, and never calls an LLM — the only model use is the embedding tier, whose failure degrades semantic ranking to lexical overlap instead of failing the turn.

Rules live in a pure domain/retrieval package (no SQL, no clock reads), the workflow in application/retrieval over consumer-owned ports, and all SQL in adapters/mssql. Owner isolation, provenance, soft delete and status rules are enforced in code at three layers.

Implemented features

  • Exact / temporal retrieval — timezone-correct window parsing (English + Persian, weekday, week, explicit date) combined with a recall verb; returns verbatim messages, never summaries, and reports exact_match_found=false rather than substituting semantics.
  • Thread, entity and anaphora retrieval — thread links via OPENJSON(thread_ids_json); relational mentions via entities_json; recent-item boosting on shared tags with an ambiguous_reference flag when the referent stays unresolved.
  • Hybrid semantic retrieval — bounded owner-scoped candidate pool plus always-on preferences; cosine rerank in Go over ai_embeddings; lexical fallback for missing, corrupt or model-mismatched vectors.
  • Embedding integration — offline deterministic embedder (default, no network) and an OpenAI-compatible /embeddings adapter; model id and dimensions travel with every vector and are validated before comparison.
  • Relevance scoring and ranking — 0.50·similarity + 0.20·recency + 0.15·importance + 0.15·thread, 21-day recency half-life, anaphora boost, 0.32 score floor, deterministic tie-breaks.
  • Deduplication — by cluster_id, normalized text and near-duplicate overlap; novelty filter drops context already present in the recent window.
  • Context-budget management — top-K 5 (7 with one extra hop), 60 tokens per item, 400 tokens total, conservative token estimation and truncation.
  • Data isolation and provenance — server-resolved user id in every port, SQL filter plus adapter and service re-checks; items without evidence never surface; rejected, superseded, highly_sensitive and invalid hypotheses are excluded.
  • Soft delete only — no code path deletes a row; ai_memory_items.deleted_at and ai_message_suppressions flag removals that retrieval excludes.
  • Failure behaviour — any store failure, timeout or cancellation returns zero items with meta.degraded=true (FB-002 / BR-023), never a partial set presented as complete.

Integration requirements

  • Migration 0017_ai_retrieval.sql must be applied before retrieval runs. It is additive and creates ai_memory_items, ai_memory_evidence, ai_memory_tombstones, ai_embeddings, ai_threads and ai_message_suppressions.
  • WP-02 must populate those tables (memory items with evidence, threads, embeddings). WP-09 only reads.
  • WP-04 owns the embedding tier. Set EMBEDDING_PROVIDER (deterministic default, or openai-compatible), EMBEDDING_MODEL and EMBEDDING_DIMENSIONS; a network embedder also needs MODEL_API_KEY. Vectors must be written as little-endian float32 with a model id.
  • WP-08 supplies TurnView.TemporalRefs and the focus thread id, and consumes RetrievalMeta to set eligibility.memory_available and the degraded constraint.
  • WP-05 / WP-10 must call Retriever.Retrieve in the parallel pre-Brain stage, pass Exclude for items already in context and issue at most one NeedsContext hop.
  • Composition: ai.NewRetrievalModule(cfg, db) wires store, embedder, clock and tunables; it rejects a nil pool instead of running memory-less.
  • Operations: no pgvector, no ANN index, no extra service. Hybrid recall is a bounded pool with in-Go cosine; volume must be benchmarked against real data before any latency claim.

Unresolved issues

Not verified here

  • SQL Server integration tests were not executed: no instance in this environment. They are opt-in via WELLBEING_INTEGRATION=true and still need a live run, including the 0017 DDL and filtered indexes.
  • Provider embeddings were never called against a real endpoint (no approved test endpoint).
  • No latency or recall-quality benchmark at scale; the contract forbids promising millisecond vector search without one.

Open decisions

  • Embedding model and dimensions (OPEN-4) — the offline deterministic embedder is a placeholder, not a semantic model.
  • Person aliases ("my sister" → "Lena") are not implemented; entity matching is literal (§7.3 open).
  • Hypothesis thread-match is validated but not strictly enforced: dropping unlinked hypotheses would contradict the inclusive proposed|supported default. Needs a review decision.
  • Full-text search is unused; the LIKE content filter in the temporal window is intentionally forgiving.
  • Persian temporal coverage is a pattern set, not a general date parser.
