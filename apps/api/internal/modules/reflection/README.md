# Daily reflections

Explicit user-authored, calendar-day entries; local/synthetic-data-only. No AI generation, memory extraction, analytics, behavioral profiling, or sharing. One active entry per (`user_id`, `entry_date`) with a SQL Server FK to the owner and filtered date+owner uniqueness (migration 0020). PUT updates the active entry; DELETE idempotently marks deletion metadata while preserving the entry. PUT after deletion creates a new row without replacing the retained content. GET/list are always owner-scoped via the signed local session. Text never enters application logs or prompts. Date is a calendar key selected by the client (no inferred timezone). The last 30 entries are listed; older entries are available by their exact date. See OpenAPI and `docs/integration/TASK08_DAILY_REFLECTIONS.md`.

Migration 0020 removes delete cascades and blocks physical deletion. Save/delete serialize on the owner row; normal GET/list queries exclude deleted entries. Permanent erasure and AI-use eligibility are separate future policies.
