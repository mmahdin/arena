# رمونا · فضای کاری مددکار اجتماعی

اپ موبایل‌اولِ مددکار اجتماعی پلتفرم «رمونا» (مدیریت میزبانی و فرزندخواندگی کودک):
برنامه روزانه، کارها، تقویم، بازدیدها، گزارش‌ها، پرونده‌ها، پایش کودک و اعلان‌ها —
کاملاً راست‌به‌چپ و فارسی.

این مخزن یک **بنیان بصری و ساختاری** برای توسعه تدریجی است: همه صفحه‌ها با دادهٔ
نمونه‌ای واقعی‌نما رندر می‌شوند و لایهٔ سرویس طوری طراحی شده که اتصال به بک‌اند واقعی
بدون تغییر در UI انجام شود.

## شروع سریع

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # بررسی انواع، بدون خروجی
npm run build      # خروجی تولید در dist/
npm run preview    # اجرای خروجی تولید
```

نیازمندی: Node 20+. فونت وزیرمتن به‌صورت محلی در `public/fonts/`_SELF-hosted است و هیچ
وابستگی شبکه‌ای در زمان اجرا وجود ندارد.

## نقشهٔ مسیرها

| مسیر | صفحه |
| --- | --- |
| `/` | امروز (برنامه روز و موارد نیازمند رسیدگی) |
| `/work` | مسیر قدیمی؛ انتقال خودکار به `/calendar` |
| `/calendar` ، `/calendar?date=YYYY-MM-DD` | تقویم جلالی و کارها و برنامه‌های تاریخ انتخاب‌شده |
| `/cases` ، `/cases/:caseId` | پرونده‌ها و صفحه پرونده خانواده |
| `/children/:childId` | صفحه کودک (روند وضعیت، پیگیری‌ها) |
| `/visits/:visitId` | جزئیات بازدید + ثبت نتیجه |
| `/reports` ، `/reports/:reportId` | گزارش‌ها و ویرایشگر گزارش |
| `/monitoring` | پایش کودکان پس از جایگذاری |
| `/notifications` | اعلان‌ها |
| `/profile` ، `/settings` | پروفایل و تنظیمات |
| `/search` | جست‌وجوی سراسری |
| `/design-system` | راهنمای زنده توکن‌ها و اجزا |
| `*` | صفحهٔ پیدا نشد |

ناوبری اصلی پنج تب است: امروز · تقویم · پرونده‌ها · گزارش‌ها · بیشتر. بقیه بخش‌ها از
طریق تب «بیشتر» یا پیوندهای درون‌صفحه‌ای در دسترس هستند تا نوار پایین شلوغ نشود.

## ساختار پروژه

```
src/
  styles/      توکن‌ها و لایه‌های پایه CSS (ترتیب importها حیاتی است)
  lib/         ابزارهای خالص: ارقام فارسی، تاریخ جلالی، برچسب‌ها، قواعد دامنه
  types/       مدل‌های دامنه (CaseFile, Visit, Task, Report, …)
  data/        db درون‌حافظه + mock/ (داده نمونه) — تنها نقطه‌ای که داده زندگی می‌کند
  services/    API درون‌اپ: توابع async با تأخیر شبیه‌سازی‌شده؛ تنها راه خواندن/نوشتن داده
  store/       settings (پوسته/حریم‌خصوصی/اعلان‌ها) و app-store (داده + intentها + toast)
  components/  ui/ اجزای پایه، layout/ پوسته و ناوبری
  features/    یک پوشه به‌ازای هر صفحه + _shared/ اجزای مشترک دامنه
  app/         AppShell (قاب دستگاه، تب‌بار، overlay) و مسیرها
```

## تصمیم‌های کلیدی

- **موبایل‌اول واقعی:** قاب تلفن در دسکتاپ فقط یک پوستهٔ نمایش است؛ چیدمان، لمس و
  سلسله‌مراتب برای عرض ~390px طراحی شده‌اند. حداکثر عرض محتوا `--app-max-w`.
- **RTL و فارسی در همه‌لایه‌ها:** `dir="rtl"` روی `html`؛ ارقام فارسی با `fa()`؛ تاریخ‌ها
  جلالی با `jalaali-js`؛ آیکون‌های جهت‌دار (بازگشت، chevron) آینه‌ای انتخاب شده‌اند.
- **توکن‌های معنایی، نه رنگ خام:** اجزا فقط `--s-*` را می‌بینند (از طریق Tailwind).
  پوسته تاریک با بازنویسی همان توکن‌ها روی `:root[data-theme='dark']` ساخته می‌شود.
- **سرویس‌ها مرز داده‌اند:** صفحه‌ها هرگز `mock` را import نمی‌کنند؛ فقط `services`.
  برای اتصال به بک‌اند، بدنه توابع `services/*` را با `fetch` عوض کنید — امضاها ثابت می‌مانند.
- **_intentها در store:_** هر جهش داده یک intent نام‌دار است (`recordVisitOutcome`،
  `submitReport`، …) تا منطق «چه چیزی پس از هر اتفاق به‌روز می‌شود» یک‌جا بماند و
  toast/اعلان/پیش‌نویس گزارش به‌صورت خودکار همراه آن بیاید.
- **فرم‌های گزارش داده‌محور:** قالب‌ها در `data/mock/report-templates.ts` تعریف می‌شوند؛
  افزودن فرم جدید = افزودن داده، بدون کامپوننت تازه.
- **حریم‌خصوصی به‌عنوان ویژگی محصول:** «حالت میدانی» نام/نشانی/شماره را محو می‌کند
  (`PrivacyText`)؛ متن‌های دسترسی و اختیار تصمیم در صفحه‌ها حضور دارند.

## افزودن قابلیت (راهنمای توسعه تدریجی)

1. **صفحه جدید:** پوشه‌ای در `features/` بسازید، از `Screen`/`ScreenHeader`/`Section`
   استفاده کنید، مسیر را در `src/app/App.tsx` ثبت کنید.
2. **داده جدید:** نوع در `types/`، نمونه در `data/mock/`، خواندن/نوشتن در `services/`،
   و در صورت جهش، intent در `app-store`.
3. **جزء جدید:** اول بررسی کنید اجزای `components/ui` کافی نیستند؛ توکن‌های معنایی و
   کلاس‌های ارتفاع لمسی (`h-9/h-11/h-12`) را رعایت کنید و حالت فشار/فوکوس بدهید.
4. **قالب گزارش جدید:** فقط یک ورودی در `report-templates.ts`.

جزئیات توکن‌ها و اجزا: `docs/DESIGN_SYSTEM.md` — جزئیات لایه‌بندی و جریان داده:
`docs/ARCHITECTURE.md`.
