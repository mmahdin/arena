# سیستم طراحی رمونا

مرجع زندهٔ توکن‌ها و اجزا. نمونهٔ قابل‌مشاهده در اپ: مسیر `/design-system`
(مقادیر رنگ را زنده از CSS می‌خواند، پس همیشه با واقعیت همگام است).

## اصول

1. **آرام و قابل‌اتکا:** سطح خنثی روشن، بنفش هویتی لوگوی رمونا، و فیروزه‌ای مکمل آن. رنگ‌های دیگر فقط برای وضعیت‌های واقعی.
   هیچ سایه‌ی سنگین، گرادیان تزئینی یا حرکت غیرضروری وجود ندارد.
2. **سلسله‌مراتب با وزن و فاصله، نه با رنگ:** عنوان‌ها درشت‌تر و سنگین‌تر؛ متون ثانویه
   با `ink-2/ink-3`؛ رنگ فقط برای معنا (وضعیت، برند، اقدام) استفاده می‌شود.
3. **یک منبع حقیقت برای فضا و شکل:** gutter صفحه `--sp-gutter` (20px)، شعاع‌ها و سایه‌ها
   توکن‌اند؛ هیچ مقدار خام دلخواه در اجزا نوشته نمی‌شود.
4. **لمسی بودن، صریح:** ارتفاع دکمه 36/44/48px، ردیف‌های فهرست ≥44px، و حالت فشار
   (`.press`) روی همهٔ اهداف لمسی.
5. **انتخاب‌پذیری بدون اتکا به رنگ alone:** حالت فعال با ترکیب پرشدگی + وزن + رنگ
   نشان داده می‌شود (تب‌بار، SegmentedControl، Chip).

## توکن‌ها (`src/styles/tokens.css`)

### رنگ — لایهٔ primitive (`--p-*`) و semantic (`--s-*`)

اجزا **هرگز** primitive را ارجاع نمی‌دهند. Tailwind فقط نگاشت‌های semantic را می‌بیند
(`bg-surface`, `text-ink-2`, `border-line`, …) با پشتیبانی alpha
(`rgb(var(--s-x) / <alpha-value>)`).

| گروه | توکن‌ها | کاربرد |
| --- | --- | --- |
| سطح | `bg, surface, raised, sunken` | پس‌زمینه اپ / کارت /.sheet / چاه‌ها و input |
| خط | `line, line-strong, line-soft` | مو، حاشیه کارت، divider |
| جوهر | `ink, ink-2, ink-3, ink-inverse` | متن اصلی / ثانویه / سوم / روی برند |
| برند | `brand, brand-strong, brand-soft, brand-muted, brand-ink` | بنفش لوگو، هویت و سطوح تأکیدی ملایم |
| اقدام | `primary, primary-fg, primary-hover` | دکمه اصلی و لینک‌های کنشی |
| تأکید | `accent, accent-soft, accent-ink` | فیروزه‌ای لوگو، دسته‌بندی یا اطلاعات مکمل |
| معنا | `success, warning, danger, info` + `-soft` هرکدام | وضعیت‌ها؛ `info` فیروزه‌ای است، سایر رنگ‌ها فقط برای معنای مستقل |

**هویت رنگی از لوگوی ارسالی:** بنفش پایه `#8F288C` و فیروزه‌ای `#24BDCD`
(وجه تیره `#15808D`) مبنای `--p-brand-*` و `--p-teal-*` هستند. پالت
`--p-neutral-*` پس‌زمینه و متن را پوشش می‌دهد؛ رنگ‌های معنایی خطر/هشدار/موفقیت
نباید با رنگ برند اشتباه گرفته شوند. برای کنتراست، از درجه‌های تیره‌تر
فیروزه‌ای در متن و درجه‌های روشن در زمینه استفاده می‌شود. نمونه‌های کنتراست
در صفحهٔ `/design-system` بر اساس مقادیر محاسبه‌شدهٔ واقعی و پوستهٔ فعال‌اند.

پوسته تاریک = بازنویسی همان semantic‌ها روی `[data-theme='dark']` (سطح‌های
بنفش-خاکستری خنثی، رنگ‌های هویتی روشن‌تر و متن با کنتراست کافی). `system` با `prefers-color-scheme` حل می‌شود.

### تایپوگرافی — وزیرمتن

| توکن | مقدار | کاربرد |
| --- | --- | --- |
| `text-2xs` | 11/16 | برچسب‌های ریز، meta فشرده |
| `text-xs` | 12/18 | meta، زمان، برچسب تب |
| `text-sm` | 14/22 | بدنه ثانویه، توضیح |
| `text-base` | 15/24 | بدنه اصلی، عنوان ردیف |
| `text-lg/xl/2xl/3xl` | 17→32 | عنوان بخش/صفحه/نمایشی |

وزن‌ها 400/500/600/700/800. ارقام با `tabular-nums` در ستون‌های عددی و با `fa()` فارسی.

### فضا، شعاع، سایه، حرکت

- فضا: مقیاس 4px تیلویند + `--sp-gutter: 20px` (کناره‌های صفحه) + `--sp-section: 28px`.
- شعاع: `xs 8 · sm 12 · md 16 · lg 20 · xl 24 · 2xl 28 · pill` — کارت `lg`، sheet بالای
  `2xl`، دکمه/چیپ `pill` یا `md`.
- سایه: `shadow-card` (بسیار ملایم)، `shadow-pop` (sheet/toast)، `shadow-ring` فوکوس.
- حرکت: `--motion-fast 140ms` و `--motion-med 240ms` با easing استاندارد؛ با
  `prefers-reduced-motion` همه‌جا خاموش می‌شود.

## اجزا (`src/components/ui`)

| جزء | نکته استفاده |
| --- | --- |
| `Button` | `variant: primary/secondary/ghost/danger` + `size: sm/md/lg`. یک اقدام اصلی در هر نما. |
| `IconButton` | هدف لمسی 44px؛ فقط با `aria-label` فارسی صریح. |
| `Card` / `ToneCard` | سطح پیش‌فرض محتوا؛ `ToneCard` برای بنرهای معنادار (هشدار/موفقیت). |
| `ListRow` | ریتم ردیف مال خود جزء است (`leading/trailing/divider/chevron`)؛ وقتی `to` بگیرد `Link` می‌سازد. تو در تو کردن کنترل تعاملی داخل آن ممنوع. |
| `Badge` / `Chip` | Badge = نمایش وضعیت؛ Chip = فیلتر/انتخاب با حالت فعال پررنگ. `ChipRail` برای ردیف افقی با fade لبه. |
| `SegmentedControl` | جایگزین تب‌های درون‌صفحه؛ انتخاب با سطح برجسته + وزن. |
| `Avatar` | فقط حروف اول روی کاشی tinted — تصویر کودک هرگز استفاده نمی‌شود. |
| `Sheet` | تنها modal اپ؛ portal به `#app-overlay`، Esc + تله فوکوس + قفل اسکرول. |
| `Toasts` | تأیید هر جهش؛ با action اختیاری («ادامه گزارش»). |
| `Field/TextInput/TextArea/Select/ScaleInput/Checklist` | کنترل‌های فرم؛ `ReportFieldControl` آن‌ها را از روی قالب داده می‌چیند. |
| `SearchBar` | ورودی جست‌وجو با focus-ring برند. |
| `Progress`, `TrendChart`, `Stepper` | نمایش پیشرفت/روند/مرحله؛ همیشه با برچسب متنی کنارشان. |
| `EmptyState`, `Skeleton`, `Loader` | حالت‌های خالی/بارگذاری یکپارچه. |
| `PrivacyText` | متن حساس؛ در حالت میدانی محو است و با لمس ۴ ثانیه آشکار می‌شود. |
| `DomainIcon` | نگاشت نوع رویداد دامنه → آیکون lucide. |

### قواعد نگارش رابط

- **یک gutter ثابت:** صفحه‌ها `px-gutter`؛ ریلهای افقی با `-mx-gutter px-gutter` لبه‌به‌لبه.
- **هدر چسبان** `ScreenHeader` (blur + `bg-bg/85`) و **فوتر اقدام** `ActionFooter`
  (چسبان پایین، بالای safe-area).
- **بخش‌بندی:** `Section` با `SectionHeader` (عنوان + action متنی برند). فاصله بخش‌ها `--sp-section`.
- **متن بلند:** `clamp-1/clamp-2` به‌جای برش دلخواه.
- **آیکون:** فقط lucide، stroke 2–2.25، اندازه 16/18/20/24؛ آیکون بدون برچسب متنی در
  اقدام‌های مهم ممنوع.

## دسترس‌پذیری

- کنتراست متن/پس‌زمینه ≥ 4.5:1 در هر دو پوسته (نمونه‌ها در `/design-system`).
- `:focus-visible` حلقه برند دوبل؛ ترتیب فوکوس طبیعی DOM؛ Sheet تله فوکوس دارد.
- هدف لمسی ≥44px؛ فاصله اهداف هم‌سطح ≥8px.
- وضعیت‌ها هرگز فقط با رنگ منتقل نمی‌شوند (آیکون/متن/وزن همراه).
- `prefers-reduced-motion` و `prefers-color-scheme` رعایت می‌شوند.
- زبان صفحه `fa` و جهت `rtl`؛ هر متن ساختاری از `labels.ts` می‌آید تا لحن یکنواخت بماند.


## الگوی فهرست خانواده‌ها

صفحهٔ خانواده‌ها یک فهرست قابل جست‌وجو است، نه مجموعه‌ای از تب‌های «فعال» و
«بایگانی». در مدل دادهٔ موجود، `closed` فقط بیانگر **پایان فرایند** است و
نباید بایگانی جداگانه بسازد؛ برچسب آن در رابط «پایان‌یافته» است و خانواده
همچنان در فهرست دیده می‌شود.

- کارت: نام خانواده **بدون برش اجباری**، نوع درخواست، نشانی در سطری جداگانه،
  سپس مهم‌ترین وضعیت بازدید. برای وضعیت نیازمند ثبت نتیجه از لحن هشدار استفاده شود.
- شناسهٔ فنی پرونده روی کارت نمایش داده نمی‌شود، اما از طریق جست‌وجو قابل پیدا کردن است.
- تقسیم‌بندی هویت رنگی خانواده‌ها فقط طبق نوع درخواست است: فرزندخواندگی بنفش،
  میزبانی فیروزه‌ای. وضعیت‌های بازدید رنگ معنایی خود را دارند.
- متن‌ها کوتاه و کاربردی باشند؛ توضیح اضافی در هدر و جداکننده‌های متعدد در
  یک خط استفاده نشوند.

## الگوی صف و مخزن

بازدیدها دو نمای مکمل دارند و هر دو از یک زبان بصری استفاده می‌کنند:

- **برنامه من:** تقویم + ردیف‌های روز. تقویم ناوبر اصلی است و ردیف‌ها `VisitRow` با ریتم
  یکسان‌اند؛ وظایف غیربازدیدی در `<details>` جمع می‌شوند تا سلسله‌مراتب حفظ شود.
- **همه بازدیدها:** ریل `Chip` با شمار هر وضعیت، سپس گروه‌های عنوان‌دار و کارت ردیفی.
  سبدها ناسازگارند (همه = مجموع چهار سبد) تا شمارها با فهرست بخوانند.
- **مخزن آزاد:** کارت تصمیم‌گیری، نه کارت پرونده. خط اول زمان + نوع بازدید + مدت، خط دوم
  محدوده، سپس یادداشت تخصیص. هیچ شناسه یا اطلاعات خانواده پیش از پذیرش دیده نمی‌شود.
  CTA «پذیرش بازدید» در هر کارت یک اقدام اصلی و 44px ارتفاع دارد.
- **هشدارها:** بنر `warning-soft` با آیکون + متن برای «نیازمند اقدام». اشاره‌گرهای بین‌بخشی
  یک‌خطی‌اند (بدون تکرار ردیف‌های بخش دیگر) و همیشه با chevron به مقصد اصلی وصل می‌شوند.

## گسترش

رنگ/وضعیت جدید = افزودن جفت semantic در `tokens.css` + نگاشت در `tailwind.config.ts` +
برچسب در `lib/labels.ts`. جزء جدید فقط اگر با اجزای موجود ساخته نشود؛ وگرنه ترکیب کنید.
کلاس dynamic (`` `bg-${tone}` ``) ممنوع — همیشه نگاشت صریح (مانند `ui/tone.ts`).
